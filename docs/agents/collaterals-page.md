# Brand Collaterals page

Collateral grid, modal and the empty, loading and error states.

- `blocks/collateral-grid/` — dynamic block `devportfolio/collateral-grid` (DPC-006/014), registered in `functions.php` after the shelf and placed in `archive-collateral.html`. `render.php` outputs `div.collaterals-grid[data-collaterals-grid]` with one `article.collaterals-item[data-collateral-categories][data-ratio]` per published collateral (menu order, then title; nothing without collaterals). The preview is page 1's thumbnail from `cptdp_get_collateral_pages()` (page 1 is the larger `srcset` candidate), else the featured image, else a numbered blank page; the tile ratio is the uncropped page ratio (blank: `1 / √2`, or `√2` when the paper size says landscape). The info band sits over the bottom of the preview and is a frosted band (`--wp--custom--glass--tint` plus `backdrop-filter: var(--wp--custom--glass--filter)`), holding the title (`h3.collaterals-item__title`, plain text) and the meta line from `devportfolio_collateral_meta_line()`. The item's one control is a separate empty `button.collaterals-item__open[data-collateral-id]`, a direct child of the article drawn over the whole item with `position: absolute; inset: 0` (named by its `aria-label`), not the title's `::after`: a filter is a containing block, so a stretched `::after` inside the band would cover only the band. The band goes opaque (`--wp--preset--color--base`, no blur) under `prefers-reduced-transparency: reduce` and `prefers-contrast: more`, in `forced-colors: active` (Canvas), and without `backdrop-filter` support. The blank is always in the markup and shows when an image fails (`view.js` hides the image). `view.js` places the items with `masonry.js` (pure: columns as many as fit at `minTileWidth()`, never fewer than 2; each tile in the shortest column; height = width / ratio) and sets each tile's `width` and `transform` and the grid height; the CSS multi-column rules are the no-JS fallback until `data-masonry` is set. It filters on `devportfolio:category-change` and re-lays out synchronously (no `requestAnimationFrame` in that handler, so the View Transition's new snapshot already has the new layout); a `ResizeObserver` re-lays out on width changes. The gap is `--collaterals-gap` (12px, 8px at 700px), read by the script. Node tests: `ddev exec --dir=/var/www/html/wp-content/themes/devportfolio/blocks/collateral-grid 'node --test tests/*.test.mjs'`. Helpers in `functions.php`: `devportfolio_collateral_item()`, `devportfolio_collateral_preview()`, `devportfolio_collateral_preview_from()` (pure), `devportfolio_collateral_meta_line()`; `devportfolio_document_category_name()` takes an optional taxonomy.
- `blocks/collateral-modal/` — dynamic block `devportfolio/collateral-modal` (DPC-007 to DPC-011, DPC-020 to DPC-022), registered in `functions.php` after the grid, placed once in `archive-collateral.html`. `render.php` outputs the desktop `dialog.collaterals-modal` (sidebar: outline close, pills, title, description, Results, Made with, Next collaterals, pinned Download and Copy link; body `.collaterals-modal__stage` with the book viewer, arrows, status line, the Tap to Flip hint and the footer pager, DPC-012/013, all from the shared modules) and the mobile `dialog.collaterals-mobile` (DPC-015..019, built by the shared `createMobileModal()` from `shared/mobile.js` with `prefix: 'collaterals-mobile'`, `viewPrefix: 'collaterals-modal'`, `eventPrefix: 'collaterals'`: the header row Close, title (ellipsis) and Download; the shared mobile viewer in the stage (swipe, edge taps, pinch and double-tap zoom, the hints and the two landscape pills, rotation fade); the footer with Pages, position, Details and the progress bar, with the round Pages and Details buttons when the footer is gone; the Pages sheet through the shared sheet controller, with the stored `thumbs` and `pageNames` and its memory per collateral; `loadDetails` imports `collateral-modal/details-sheet.js`, the Details sheet with `collateralDetailsModel()` (pure, sections only when they have data), Download and Copy link, closing without changing rotation; the mobile dialog swaps with the desktop one keeping the collateral and page, `mobile-viewer` in `shared/`), plus `<script type="application/json" class="collaterals-modal__data">` with `{ order, items }` from `devportfolio_collateral_modal_payload()` (published collaterals in the grid's order; plain text and URLs only, `JSON_HEX_TAG | JSON_HEX_AMP`). `view.js` opens on `[data-collateral-id]`, pushes `?collateral_slug=` on a click, replaces it when a Next thumbnail swaps the collateral (`data-collateral-next`), steps back on close, and swaps desktop and mobile in place on resize; it imports `shared/routing.js`, `shared/download.js` and `shared/deeplink.js` (`createDeeplink( 'collateral_slug' )`). Pure modules: `next.js` (`nextTwo()`: two after the current one, wrapping, within the active filter pill) and `copy-link.js` (`linkFor()`, `copyText()`: Clipboard API, then `execCommand`, then the selected field); both are one-function wrappers over `shared/next-items.js` and `shared/copy-link.js` (DPV-026; `linkFor( location, slug, param )`, here with `collateral_slug`). Desktop book (DPC-012/013): `view.js` builds `createViewer({ prefix: 'collaterals-modal', … onTap })` from `shared/viewer.js` and `createPagerController({ prefix: 'collaterals-modal', eventName: 'collaterals:modal-change' })` from `shared/pager-controller.js`; `openPages()` sets the footer before the dialog shows (stored pages, else `cptdp_total_pages`, a spread only for portrait); the payload carries the Documents viewer keys (`kind`, `images`, `ratio`, `viewerUrl`, `nativeUrl`, `pdfBytes`, `pages`, `fileType`, `format`, `pageNames`/`thumbs` when stored) built by `devportfolio_document_viewer_data()` through `devportfolio_page_source_map()`. Tap to Flip: `.collaterals-modal__tap` shows only on touch, in a two-page view, unflipped and not zoomed (`shouldShowTapHint()`). Its Documents viewer CSS is the same `blocks/document-modal/style.css` (selectors listed for both prefixes, enqueued on the Collaterals archive as `devportfolio-viewer`). Events `collaterals:modal-change` (desktop) and `collaterals:mobile-change` (mobile) carry `{ id, page, step, pages }`; `collaterals:mobile-pages` and `collaterals:mobile-details` are the footer and round buttons' events. Every collateral kind the Documents viewer accepts is drawn (PDF, Office, and `image` = one stored page, which `canShowOnMobile()` lets through). Helpers in `functions.php`: `devportfolio_collateral_pill()`, `devportfolio_collateral_stats()`, `devportfolio_collateral_thumb()`, `devportfolio_collateral_modal_payload()`, `devportfolio_collateral_modal_strings()`; `devportfolio_document_download_target()` takes the file meta key; `devportfolio_collateral_single_redirect_url()` and `devportfolio_modal_single_redirect_url()` share the single-to-deeplink redirect with the documents one (hooked as `devportfolio_redirect_document_single`).
**Collateral empty, loading and error states (v0.27.0, DPC-025):** the Brand Collaterals page and both modals now say what is happening instead of showing a bare blank, in five states. **(A) No collaterals at all:** the title plus one line, `No collaterals yet.` (`p.collaterals-empty.collaterals-empty--none`, `role="status"`, rendered instead of the grid), and the category pills are hidden by `.documents-page__content:has(.collaterals-empty--none) .wp-block-devportfolio-document-categories { display: none; }` (`:has()` is the only mechanism; an older browser shows the pills above the line, untidy but not broken). **(B) A category with no collaterals:** the grid renders as usual and a sibling *after* it, `p.collaterals-empty[data-collaterals-empty]` (`role="status"`, `hidden`, text `No collaterals in this category`), is toggled synchronously by `blocks/collateral-grid/view.js`, which reads the count returned by its own `filter()`; `masonry.js` has the pure `matchesCategory()`/`visibleCount()` so the count is testable without a DOM, and the line appears on first paint for `?category=<empty>` (no flash, no extra request). **(C) Failed / `needs_browser` / no file** (`none`): the tile stays the numbered blank, the modal shows the existing "can't be previewed" line plus its hint, Download works, and there is **no pager, arrows or tap hint** (the payload reports zero pages). **(D) `pending`** (a conversion is queued or running): the tile draws `img.collaterals-item__loading` (the plugin image, `alt=""` and `aria-hidden="true"` so it is decorative; the meaning lives in the open button's `aria-label`, which gains the suffix ` (preview is being prepared)`), pulsing in CSS (removed under `prefers-reduced-motion: reduce`, and the image is replaced by a plain outline in `forced-colors: active`); the modal shows `Preview is being prepared. You can still download the file.` with the same image and **no chrome** (pager, arrows, tap hint, footer and progress bar all hidden because the payload's `pages` is zeroed before first paint — `openPages()` in `blocks/collateral-modal/view.js` for the desktop dialog, `blocks/shared/mobile.js` for the mobile one); Download still works. **(E) wp-admin** shows the same image in the Collaterals list Thumbnail cell and in the Page images meta box for a `pending` collateral only — a featured image or a real page-1 thumbnail always wins, and `failed`/`needs_browser`/`none` keep the dash. **Plugin API** (`includes/post-types/document-pages.php`): `cptdp_get_collateral_pages_status( $id )` returns the stored `CPTDP_Page_Store::get_status()` for a collateral and `''` for anything else; `cptdp_collateral_loading_image_url()` returns `assets/collateral-loading.svg` (a static greyscale SVG in the plugin, no script or external reference, **so the theme still ships no image files** — the theme only reads it and degrades to nothing when the function is missing); `cptdp_collateral_admin_loading_html( $id, $width = 50 )` renders the admin `<img>` with the paper-size ratio (portrait `√2`, landscape `1/√2`), `alt=""`, a `title` of `Preview is being prepared`, and returns `''` for any status other than `pending`. **Theme API:** `devportfolio_collateral_preview_from()` gained `string $state = ''` and returns `loading`; `devportfolio_collateral_preview()` reads the plugin status (page set or featured image still win) and `devportfolio_collateral_thumb()` supplies the URL for `loading`; the modal payload gained **`previewState`** (`ready` when the item has stored images or a `viewerUrl`, `pending` when the status is `pending`, else `unavailable`) and the viewer strings gained `pending` and `loadingImage`; `devportfolio_viewer_status()` emits `data-pending`, `data-loading-image` and a hidden `<img class="<prefix>__state-image">`. `devportfolio_document_viewer_data()` never sets `previewState` and the Documents strings have no `pending`/`loadingImage` keys, so the Documents page, its payload and its viewer behave exactly as before (the unused hidden `<img>` is the only new markup). Shared JS: `blocks/shared/status.js` gained the `pending` state (text, hint cleared, `aria-busy`, spinner ↔ image), and `viewer.js`/`mobile-viewer.js` pass the payload's `previewState` through as `emptyState`.
