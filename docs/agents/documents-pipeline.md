# Document and collateral page pipeline

Page images, Office and Word conversion, page names, thumbnails and the featured image, for documents and collaterals.

**Document page images (v0.19.0, DPB-025):** when a `document`'s PDF is created or changed (`added/updated_post_meta` on `cptdp_document_file`, `save_post_document` at priority 99, attachment edits) `CPTDP_Page_Scheduler::ensure()` (`includes/documents/`) clears stale images and picks a producer per Settings → Documents `pages_mode` (`auto` default, `server`, `browser`): the server converts in a WP-Cron job (`CPTDP_Page_Converter`, Imagick then Ghostscript; the save never converts), and when it cannot (or fails in `auto`) the status becomes `needs_browser` and the 'Page images' meta box on the edit screen renders the pages with the plugin's vendored pdf.js (`assets/vendor/pdfjs/`, 4.10.38) in the admin's browser and uploads them through admin-only REST routes (`includes/documents/class-page-rest.php`, `cptdp/v1/documents/<id>/pages...`, `edit_post` + nonce, each upload validated). Images live in `uploads/cptdp-pages/<attachment_id>-<hash8>-<document_id>/p-001.webp` (one folder per document; sets made before the document id was added keep the older `<attachment_id>-<hash8>` name); manifest and status in non-REST post meta `cptdp_document_pages`, `cptdp_document_pages_status` (`none|pending|ready|needs_browser|failed`), `cptdp_document_pages_error`; valid only while the PDF fingerprint matches and the count equals `cptdp_total_pages` when set. API for the theme: `cptdp_get_document_pages()`, `cptdp_document_pdf_url()`, `cptdp_document_pdfjs_urls()`. Documents list has a Pages column and a notice. WP-CLI: `ddev wp cptdp pages generate [<id>|--all] [--force] [--sync]`, `pages clear`, `pages status` (run `generate --all` once to backfill documents saved before this feature). No public conversion route exists: visitors never trigger server work. Hardening and behaviour added after review: a replaced PDF during a running conversion is detected and re-queued (the stale output is deleted), a held conversion lock reschedules itself (1 minute, up to 10 times, then hands over to the browser), Imagick failures on the engine itself retry with Ghostscript, Ghostscript refuses PDFs over the page cap like Imagick (filter `cptdp_pages_max_pages`), a PDF must start with `%PDF-` and is read as `PDF:`, stored folder names are validated and only direct children of `cptdp-pages` are ever deleted, the admin browser run uses a run token (`start` returns it, answers 409 while another tab runs unless `force` is sent), and a partial REST update of Settings → Documents keeps the saved values of missing keys (only the settings form treats an unticked box as off).

**Bottom trim:** `CPTDP_Page_Analyzer` (`includes/documents/class-page-analyzer.php`) reads a 300px-wide copy of each page's lower 30% (Imagick, GD fallback) and counts blank rows from the bottom (a row is blank when at least 99.8% of its pixels are within 8/255 of white); the document's `crop_bottom` is the SMALLEST blank share over ALL pages minus a 2.5% kept margin, 0 under 2%, capped at 25% (every page must keep the same size). It is measured when the images are made (server conversion, or the admin script, which runs the same maths and sends `cropBottom` on finish; a test compares the constants of both), stored in the manifest, and never changes the image files. `cptdp_get_document_pages()` returns `crop_bottom` and a `ratio` already for the visible part (`width / ( height * ( 1 - crop ) )`); both are 0 when Settings → Documents `trim_bottom` (checkbox, default on) is off, no regeneration needed. A printed footer such as 'Page 1 of 6' is content, so documents that have one are not cropped. `ddev wp cptdp pages recrop [<id>|--all]` recomputes it from the stored images; `pages status` shows a `crop` column.

**Selectable text:** Settings → Documents → **Native viewer** `native_pdf` (default off; it was called `selectable_text`, an old stored value is still read as `native_pdf`) makes the viewer draw pages with pdf.js and a real text layer instead of the stored images (the theme root gets `data-selectable-text="1"`) ; see the viewer notes below.

**Presentations (v0.20.0, DPB-026):** a document's file may also be a `.pptx`, `.ppt` or `.odp` (`CPTDP_Page_Store::kind_of_attachment()`: mime type, or the extension when the host reports a generic type; `get_source()` returns `kind`; `source_attachment_id()` accepts PDFs and presentations while `pdf_attachment_id()` and `cptdp_document_pdf_url()` stay PDF only, so the viewer never hands a presentation to pdf.js). They go through the same pipeline (`ensure()`, cron job, `CPTDP_Page_Converter::convert()`), with one extra step: `CPTDP_Pptx_Converter` (`includes/documents/class-pptx-converter.php`) validates the file by content (`inspect()`: zip bomb limits of 5000 entries, 1 GB expanded, ratio 200, 100 MB (filter `cptdp_pptx_max_bytes`); `.pptx` needs `[Content_Types].xml` and `ppt/presentation.xml` and refuses macros and external `oleObject`/`package`/`frame`/`externalLink` relationships; `.odp` needs `mimetype` as its first entry and refuses `Basic/`, `Scripts/` and external `draw:object`/`object-ole`/`plugin` hrefs; `.ppt` needs the OLE2 signature and is refused when the file contains the UTF-16 name `_VBA_PROJECT`), then runs LibreOffice headless (`soffice --convert-to pdf:impress_pdf_Export` through `proc_open` with an argument array, a fresh `-env:UserInstallation` profile and its own HOME in a `cptdp-pptx-*` temp folder, 120 s timeout (filter `cptdp_pptx_timeout`), one run at a time through the transient `cptdp_pptx_lock`) to make a temporary PDF that the unchanged PDF code turns into images; the temporary folder is always removed.

**Server only:** no browser can read these files, so a presentation never becomes `needs_browser`: without LibreOffice (`CPTDP_Pptx_Converter::binary()`, `is_available()`, filters `cptdp_pptx_soffice_path` and `cptdp_pptx_available`, constant `CPTDP_SOFFICE_PATH`) or on any conversion error the status is `failed` with a message that recommends uploading a PDF, whatever `pages_mode` says; the admin-browser routes `start`, `<n>` and `finish` answer 400 `cptdp_pptx_server_only`, and the new admin route `POST cptdp/v1/documents/<id>/pages/retry` (`edit_post`) queues the server again (the Regenerate button of a presentation uses it). The manifest carries `source_kind` and `converted_via` (`libreoffice`) for presentations only (a missing `source_kind` means a PDF) and **presentations are never bottom-trimmed** (`crop_bottom` is 0 and ignored). Status text: `Ready, 12 slides (converted from PowerPoint)`.

**Warning:** `cptdp_pptx_warning( $kind )` (`includes/post-types/document-presentations.php`) says the conversion may be imperfect and recommends exporting to PDF; it shows live in the media picker when a presentation is chosen or uploaded (`assets/admin-document.js`, data `cptdpDocument.pptxWarnings`), persistently in the Document File and Page images meta boxes, and once after saving; for `pptx` and users who can `manage_options` it ends with a link (new tab) to the Native viewer section (`options-general.php?page=cptdp-documents#cptdp-native-viewer`), or a status line when it is on.

**Native viewer for PowerPoint:** Settings → Documents → Native viewer → PowerPoint (`native_pptx`, default off; nothing is sent to anyone) makes `cptdp_document_native_pptx_url( $post_id )` return the attachment URL of a `.pptx` (never `.ppt` or `.odp`, which the viewer cannot read; filter `cptdp_native_pptx_max_bytes`, 30 MB), whether or not converted slides exist: the theme's modal then draws the original file in the visitor's browser with selectable text, and the converted slides are only its fallback (see the document modal notes). On a host without LibreOffice a `.pptx` is then not marked failed (status `none`). Settings → Documents → Document conversion also shows whether PowerPoint conversion is available (with the LibreOffice version). `pages status` has a `kind` column. DDEV installs `libreoffice-impress`, `libreoffice-calc` and metric-compatible fonts (`webimage_extra_packages` in `.ddev/config.yaml`; run `ddev restart`; the WP test library then needs `install-wp-tests.sh` again).

**Spreadsheets (v0.21.0, DPB-027):** a document's file may also be an `.xlsx`, `.xls` or `.ods` (`CPTDP_Page_Store::SPREADSHEET_MIMES`, `is_spreadsheet_kind()`, `is_office_kind()` = presentation or spreadsheet, which the scheduler, converter, REST routes, manifest marks and no-trim rule now test). Same pipeline and the same `CPTDP_Pptx_Converter::to_pdf()` (one soffice at a time, throwaway folder and profile, 120 s), with Calc's export filter from `CPTDP_Xlsx_Converter::export_filter()`: **one page per sheet** (`pdf:calc_pdf_Export:{"SinglePageSheets":...}`, filter `cptdp_xlsx_single_page_sheets`). Because sheets come out at the size they need, `CPTDP_Page_Converter::read_sheet_page()` reads each page's size first (a 72 dpi ping, no drawing) and then draws it **once**, at the resolution that fits it on one **1800x1273 white canvas** (small sheets sharper up to 2x, big ones shrunk, placed top left with `extentImage`; `read_page()` is the shared flatten-to-sRGB reader), so the book gets one page shape; spreadsheets are never bottom-trimmed. `CPTDP_Xlsx_Converter` (`includes/documents/class-xlsx-converter.php`) holds the content checks (`inspect()`, 25 MB default, filter `cptdp_xlsx_max_bytes`, same zip-bomb limits; `.xlsx` refuses macros, `xl/externalLinks/`, `xl/connections.xml`, `xl/queryTables/` and external object relationships; `.ods` refuses `Basic/`, `Scripts/` and external `xlink:href` on objects, tables and cell-range sources; `.xls` is an OLE2 file scanned for `_VBA_PROJECT`; the OLE scan (`CPTDP_Pptx_Converter::ole_status()`), the relationship check (`rels_have_external_object( $xml, $extra )`) and the ODF href check (`odf_has_external_object( $xml, $elements )`) are shared with presentations, the spreadsheet only passes its extra types and elements), `calc_installed()` (looks for `libsclo.*` next to the soffice binary, cached per request: Impress alone is not enough), and `write_profile()`, which writes a Calc profile that **never updates links, never recalculates on load (the saved values show) and disables macros**. `CPTDP_Pptx_Converter::is_available( $kind )` takes the kind (a spreadsheet also needs Calc; filters `cptdp_pptx_available` and `cptdp_xlsx_available`, both must allow it) and `unavailable_reason( $kind )` has Excel wording. Server only, never `needs_browser`; the browser upload routes still answer 400 `cptdp_pptx_server_only` (the code kept for compatibility). Without LibreOffice or Calc a spreadsheet is `failed` with a PDF recommendation, except a `.xlsx` with `native_xlsx` ticked (status `none`). The shared Office pieces live in `includes/post-types/document-office.php`: `cptdp_office_warning()` / `cptdp_office_warnings()` (dispatch by kind), `cptdp_office_warning_html()` (the warning chrome: first paragraph plus the Native viewer link paragraph for users who can `manage_options`), `cptdp_native_viewer_enabled( $kind )` (the setting for a kind that has a switch; the scheduler uses it to leave a `.pptx`/`.xlsx` at status `none` on a host without LibreOffice) and `cptdp_native_office_url()` (kind, setting and size rules; `cptdp_document_native_pptx_url()` and `cptdp_document_native_xlsx_url()` are one-line wrappers). Only the wording lives in `document-presentations.php` (`cptdp_pptx_warning()`) and `includes/post-types/document-spreadsheets.php` (`cptdp_xlsx_warning()`); they warn in the media picker (the localized `pptxWarnings` now holds every Office kind), the Document File and Page images boxes and once after saving; the warning says everything on visible sheets is published, and for `.xlsx` and administrators links to the Native viewer section. Status text `Ready, 3 pages (converted from Excel)`.

**Native viewer for Excel:** Settings -> Documents -> Native viewer -> Excel (`native_xlsx`, default off) makes `cptdp_document_native_xlsx_url( $post_id )` return the attachment URL of a `.xlsx` (never `.xls`/`.ods`; filter `cptdp_native_xlsx_max_bytes`, 15 MB); the Document conversion section shows its availability. The visitor downloads the whole workbook, **hidden sheets and comments included** (the viewer only skips drawing hidden sheets). DDEV installs `libreoffice-calc` too.

**Word documents (v0.22.0, DPB-028/DPD-028):** `document` files may also be `.docx`, `.doc` or `.odt`; `CPTDP_Page_Store` detects them as `docx`, `doc` and `odt`, validates them with `CPTDP_Docx_Converter`, and converts them server-side with LibreOffice Writer (`pdf:writer_pdf_Export`). Word files are server-only, never `needs_browser`, are never bottom-trimmed, and successful conversion overwrites `cptdp_total_pages` with the generated page count. The conversion row is `word`; the native setting is `native_docx`, which only exposes `.docx` files up to 10 MB through `cptdp_document_native_docx_url()`. The native viewer is the bundled `DocxScrollViewer` in `blocks/shared/vendor/ooxml/`, loaded lazily with the pinned `0.89.7` asset URLs; it provides selectable text and falls back to converted pages. `.doc` and `.odt` always use converted pages. Writer conversion requires `libreoffice-writer` in DDEV; regenerate `tests/fixtures/sample.docx`, `sample.doc` and `sample.odt` from `sample.fodt` with LibreOffice when fixtures change.

**Page names and thumbnails (v0.23.0, DPB-030/031):** when a document's pages are made, the plugin also makes a **name per page** and a **small thumbnail per page**, both stored with the page set and returned by `cptdp_get_document_pages()` as `names` (one string per page, `''` where none, `[]` when the file has none), `name_ranges` (`[ [ first_page, title ], ... ]`), `thumbs` (URLs, `[]` when any is missing, so a half set is never used), `thumb_width`, `thumb_height`. **Names** (`CPTDP_Page_Outline`, `includes/documents/class-page-outline.php`): a small read-only pure-PHP PDF reader (no Ghostscript or Imagick outline dump exists; it scans `N G obj`, reads the catalog, page tree, outline, name trees and object streams, bounded by `cptdp_outline_max_bytes` 50 MB, `cptdp_outline_timeout` 15 s and 2000 entries, gives nothing for encrypted or malformed files, and never fails a conversion) maps bookmarks to pages; a bookmark names its page and every page after it until the next one, the deepest bookmark starting on or before the page wins. **PDF** from the PDF itself, **Word** from the temporary PDF LibreOffice Writer writes (its filter now sets `ExportBookmarks`, so headings become bookmarks), **Excel** from `CPTDP_Xlsx_Converter::sheet_names()` (visible sheets only, from `xl/workbook.xml` or the ODS `content.xml`, trusted only when the count equals the page count; `.xls` has none), **PowerPoint** blank. Stored in the manifest as `page_names` ranges (omitted when none). **Thumbnails** (`CPTDP_Page_Thumbs`): `t-001.webp` beside `p-001.webp`, 240px wide, webp quality 65 (45 when over 20 KB), made from the page already in memory (Ghostscript sets, and sets whose in-memory thumbnails failed, get them from the stored images), always from the uncropped page; manifest `thumb_width`/`thumb_height`. A set without thumbnails is valid and is not re-queued. Browser-made sets: the admin script (`assets/admin-document-pages.js`) draws and uploads each thumbnail (`POST .../pages/<n>?thumb=1`, at most 280px wide and 100 KB) and sends `pageNames` from `pdf.getOutline()` on `finish`; the finish step keeps thumbnails only when the whole set is valid (else the server makes them if it has Imagick). WP-CLI backfills without converting again: `ddev wp cptdp pages thumbs [<id>|--all] [--force]` (resizes the stored page images), `ddev wp cptdp pages names [<id>|--all]` (PDF and Excel from the stored source; a Word document needs `pages generate <id> --force` once because its converted PDF is not kept); `pages status` has `names` and `thumbs` columns.

**Admin:** the Documents list Thumbnail column shows the featured image if there is one, else the page-1 thumbnail (`cptdp_document_admin_thumb()` / `cptdp_document_admin_thumb_html()`, the same file the mobile Pages sheet draws for page 1; a set made before thumbnails falls back to the first stored page image scaled by CSS), lazy and low priority with a reserved box; the column is 90px wide; the Page images box on the edit screen shows it too. A featured image is made from page 1 when a set becomes ready (DPC-023, see *Featured image from page 1* below). Thumbnail URLs are immutable (the folder name carries the file fingerprint), so the host can cache `uploads/cptdp-pages/**.webp` for a year (`Cache-Control: public, max-age=31536000, immutable`); this is a host setting, not set by the plugin.

**Collateral page images, names and thumbnails (v0.26.0, DPC-023):** a `collateral` gets the same stored page images, page names and thumbnails as a document, made by the same pipeline in `includes/documents/`.

**Registry:** `CPTDP_Page_Store::SOURCE_META` (`document` => `cptdp_document_file`, `collateral` => `cptdp_collateral_file`) with `post_types()`, `supports( $id )` and `file_meta_key( $id )`; every hook, query, route, CLI target, meta registration, meta box, admin script and list notice asks it instead of comparing with `'document'` (a third type is one array entry; no filter on purpose). `posts_using( $attachment_id )`, `CPTDP_Page_Scheduler::post_ids( $status, $types )` and `posts_with_source( $types )` replace the old `documents_using()`, `document_ids()` and `documents_with_pdf()`. **The stored meta keys keep their `cptdp_document_pages*` names (`_status`, `_error`, `_source`) on collaterals too, and the cron hook stays `cptdp_convert_document_pages`**, so no document is migrated.

**File types a collateral accepts:** PDF (server or browser, `pages_mode` applies, trimmed, bookmarks name pages, `t-NNN` thumbnails), Office files (as documents: LibreOffice, server only) and raster images `image/jpeg|png|webp|gif` (new kind `image`, `CPTDP_Page_Store::KIND_IMAGE`/`IMAGE_MIMES`, `is_image_kind()`; `is_server_only_kind()` = Office or image). An image is only a source for a collateral (`source_kind()` returns '' for a document) and becomes **one page** through `CPTDP_Image_Page_Converter` (`includes/documents/class-image-page-converter.php`, built on `wp_get_image_editor()`: validated by content with `wp_getimagesize()` (its mime must match the attachment's), refused above `cptdp_image_max_pixels` (40 MP) before decoding, resized to 1400/1800 wide like a PDF page and never upscaled, WebP when the editor can write it else JPEG, `t-001` at 240 wide; a set without a thumbnail is valid), server only (`pages_mode` ignored, never `needs_browser`; without an image editor `failed` "This server cannot process images."), never trimmed, manifest `source_kind: image`, `converted_via: image-editor`; status text `Ready, 1 page (from an image)`. **SVG is refused** (rasterising needs an Imagick SVG delegate, and SVG is an attack surface): status `none`, and the Page images box says to upload a PNG or PDF export; `cptdp_collateral_sanitize_file()` still accepts SVG as the download.

**Page count:** for a collateral `cptdp_total_pages` always follows the file (`save_manifest()` and `reconcile()` overwrite it, like Word), so a typed or seeded count is corrected instead of marking the set failed; documents keep the check.

**API:** `cptdp_get_collateral_pages( $id )` (`document-pages.php`) returns the same array as `cptdp_get_document_pages()`, for collaterals only, valid only while the file fingerprint matches, and never converts or writes; the theme viewer ticket reads it.

**REST:** the same five admin routes under `cptdp/v1/collaterals/<id>/pages...` (`CPTDP_Page_REST::ROUTE_BASES`, `route_for( $id )`); a route answers 404 "Not found." for a post of the other type; an image source answers 400 `cptdp_server_only` on `start`/`<n>`/`finish` (Office keeps `cptdp_pptx_server_only`).

**Admin:** the Collaterals list has the Page images column and the page-1 Thumbnail fallback (one shared `cptdp_pages_status_cell()` for both lists); the Page images meta box (`add_meta_boxes`, every registered type) and the needs-browser list notice work on both.

**WP-CLI:** `ddev wp cptdp pages generate|clear|status|recrop|thumbs|names|featured` take a document or collateral ID; `--all` covers both and `--post_type=document|collateral` narrows it; `pages status` has `type` and `featured` columns. Tests: `tests/collaterals/test-collateral-pages.php` (`CPTDP_Test_Collateral_Pages`); the shared PDF outline builder `outline_pdf()`, `make_collateral()` and `make_image_attachment()` live in `CPTDP_Pages_Test_Case`.

**Shared page image settings (DPC-023):** Settings -> Documents has a section **"Page images (Documents and Brand Collaterals)"** (`cptdp_documents_page_images`, anchor `#cptdp-page-images`) holding `pages_mode`, `trim_bottom` and `featured_from_page`; its intro says they apply to both pages, and the "Documents" section keeps only the book title ("Options for the Documents page only."). The option is still `cptdp_documents` with the same keys, and the menu title and slug stay "Documents" (the Office warnings link to it). The Page images box on both edit screens links administrators to the section ("Page image settings (shared with Documents/Brand Collaterals)").

**Featured image from page 1 (DPC-023, documents and collaterals):** `CPTDP_Page_Featured` (`includes/documents/class-page-featured.php`). When `save_manifest()` leaves a set `ready` (server or browser producer) and the post has no featured image, page 1 (`p-001` read from the validated folder, uncropped, copied and added with `media_handle_sideload()` so WordPress makes its sub-sizes; file `<slug>-page-1.<ext>`, parent = the post) becomes the featured image. Ownership: post meta `cptdp_featured_generated` (not in REST) names it; the attachment carries `_cptdp_generated_for` (the post) and `_cptdp_generated_from` (the set folder), so the same set never makes a second copy. **An image an editor chose is never replaced or deleted.** A new file keeps the old generated image until the new set is ready, then swaps it (the old attachment is deleted). Removing the file deletes ours while it is still the featured image; deleting the post deletes ours; an editor deleting ours in Media clears the record. A failure is written to `cptdp_document_pages_error` prefixed `Featured image: ` and never changes the page status. Switch: `featured_from_page` (default **on**; off keeps the images already made). Existing documents get one on their next conversion or with the backfill `ddev wp cptdp pages featured [<id>|--all] [--post_type=...] [--force]` (`--force` remakes ours only). Tests: `tests/collaterals/test-page-featured.php` (`CPTDP_Test_Page_Featured`, every case for both types) and the settings cases in `tests/settings/test-documents.php`.
