## Context
- Present: `devportfolio/document-book` (cover only) and `devportfolio/document-categories`. `archive-document.html` currently holds a **temporary** Query Loop of placeholder books (uncommitted, marked TEMP). There is no shelf item yet (DPD-016), so there is nothing "clickable" to attach the modal to except that fixture.
- `document` CPT stores: `cptdp_document_file` (attachment ID), `cptdp_embed_url`, `cptdp_filetype`, `cptdp_total_pages`, `cptdp_author`, statistics. Helper `devportfolio_document_format_label()` already builds `PDF · 24 pp`.
- **Two data gaps** (see Risks 1 and 2): `document` has **no software tools meta** (`cptdp_software_tools` exists on `video` and `collateral` only) and **no description field** (supports `title, editor, thumbnail, page-attributes, custom-fields`, no `excerpt`).

## Key decisions
1. **Native `<dialog>` + `showModal()`**: free focus trap, `Esc`, top layer, inert page. The dimmed backdrop is the dialog's own `::backdrop`; backdrop click = a click whose `event.target` is the `<dialog>` element itself (the dialog has no padding, an inner `.documents-modal__panel` fills it). Matches the hi-fi (`vback`/`vmodal`) without `role="dialog"` bookkeeping.
2. **One dynamic block `devportfolio/document-modal`** (`blocks/document-modal/`: `block.json`, `render.php`, `style.css`, `view.js`), placed once in `archive-document.html` after the content group. It renders **one shared `<dialog>`** (header, empty body, footer) plus a JSON payload of all published documents (`<script type="application/json" id="documents-modal-data">`: id, title, description, tools[], format label, pages, download URL). `view.js` fills the dialog from the payload when a book is opened. Chosen over one dialog per document (24+ hidden dialogs, and DPD-013 would multiply page markup) and over fetching REST on click (extra request, no gain for a portfolio-sized set). Payload built in PHP with the existing helpers, escaped with `wp_json_encode` + `JSON_HEX_TAG` (no `</script>` break-out).
3. **Open trigger contract (works before DPD-016):** any element inside `[data-documents-shelf]` or the temp query with `data-document-id="<postId>"` and an interactive role opens the modal; `view.js` uses one delegated click listener on `document`. `render.php` of `document-book` stays cover-only. Until DPD-016 exists, the `document-book` cover itself carries `data-document-id` (as built; no fixture wrapper needed). The info under the cover and keyboard access come with the DPD-016 item button, which must carry the same attribute. The real shelf item (DPD-016) must carry `data-document-id` on its button. Documented in AGENTS.md as the contract.
4. **Breakpoint 700px** (ticket) via `window.matchMedia( '(min-width: 701px)' )`. At 700px and below the click is ignored (no modal; DPD-017 will take over). If the viewport shrinks to 700px or less while open, the modal closes (listener on the media query). The book grid's 820px breakpoint is unrelated and unchanged.
5. **Size and look (DPD-009):** `width: min(1680px, 100% - 32px)` and `height: 100dvh - 32px` (changed from the ticket's ~940px so documents are readable), full-screen at 1200px and below, centred, `1px` `--edge`/`--line` outline, `--r-tile` radius, `--shadow-sheet`, backdrop `rgb(0 0 0 / .5)` + `blur(6px)` (hi-fi `--scrim`). Open animation = hi-fi `pop` (translateY 10px + scale .985, 260ms); disabled under `prefers-reduced-motion` and fade-only is not needed. Body scroll lock via `overflow: hidden` on `<html>` while open (restore on close). Body area: empty `div.documents-modal__body` with `min-height` (about 360px) so the blank modal has presence, `aria-live="polite"` region reserved for DPD-013.
6. **Header (DPD-010):** left = `<h2 id=...>` title (hi-fi is sans 22px/500; the **ticket says bold serif, larger**: follow the ticket, Georgia, 700, 26px, `-.015em`; open point 3) and a one-line description under it (`--subtle`, 14px, single line with `text-overflow: ellipsis`). Right = software tags as small pills (`<ul>` of `li`, hidden entirely when none) then **one** pill `PDF · 24 pp` (reuse `devportfolio_document_format_label()`; same pill style as the hi-fi `.fmt`), then the Download button and the Close slot. Thin `1px` divider under the header (`border-bottom`). Wraps on narrow desktop widths (701-900px): title block `flex: 1 1 280px`, meta wraps below.
7. **Download (DPD-012):** filled dark `<a class="documents-modal__download" download>` (a link, not a button, so the browser does the download natively and middle-click/long-press work), icon (hi-fi SVG `M12 4v11M7 11l5 5 5-5M5 20h14`) + label `Download`, `aria-label="Download <title>"`. `href` = `wp_get_attachment_url( cptdp_document_file )`. **Shown for every document** (ticket): if a document has no uploaded file the link falls back to `cptdp_embed_url` (opens in a new tab, `rel="noopener"`, no `download` attribute); if neither exists the button is still rendered but `aria-disabled="true"`, dimmed, `href` removed (Risk 4). Position far right, immediately left of Close.
8. **Close (DPD-015):** an X icon button `button.documents-modal__close` (36px, 6px radius like the hi-fi `.iconbtn`, `aria-label="Close viewer"`, 18px stroke icon) at the top right of the modal, **in line with the header**. It is the **last control inside `.documents-modal__meta`**, in the same flex row as the format pill and Download, with the same 36px height and `align-items: center`, so the X and Download share one centre line (an absolutely positioned X at `top: 14px` could not do this). Header right padding is 20px (no reserved corner). The row stays together if the header wraps. Closing three ways: the X (`dialog.close()`), **Esc** (native `<dialog>` `cancel` then `close`; no `cancel` listener may block it) and the dimmed backdrop (decision 1). One `close` listener restores page scroll and returns focus to the opener, so all three paths behave the same. Focus lands on the X when the modal opens (hi-fi).
9. **Footer (DPD-011), desktop only:** `<footer>` with `nav.documents-modal__pager[aria-label="Pages"]` and the page indicator row (`text · progress bar`). Both are `display: none` at `max-width: 700px` (DPD-019 owns mobile). The pager algorithm is a **direct port of the hi-fi `pagnItems()` / `draw()` / `norm()` / `turn()`**:
   - Two-page view on desktop whenever `pages > 1` (always starts on an odd page: `norm()` subtracts 1 from an even page); single view for 1 page. Page orientation does not exist in the data, so no landscape single-page mode (Risk 5).
   - `pages <= 9`: every number. Longer: always 1 and last, window of 3 on each side (single) or 2 on each side (two-page view) around the visible pages, `···` for gaps; **a gap of exactly one page shows that page instead of `···`** (hi-fi behaviour; the ticket example `1 ··· 9 10 [11] [12] 13 14 ··· 24` is unaffected).
   - Visible pages get `.on` + `aria-current="page"` (both when two are visible, filled `--primary`). `‹ Back` / `Next ›` use `aria-disabled="true"` plus dimmed 35% opacity and `pointer-events: none` on the first and last view; Back/Next move by the step (2 or 1).
   - Clicking a number sets the current page through `norm()` (e.g. clicking 12 starts the view at 11).
   - Hidden (`hidden` attribute) for 1-page documents; the indicator still shows.
   - Indicator: `Pages 11–12 of 24` (two visible), `Page 5 of 24` (one), en dash, tabular numerals. Bar fill = `lastVisible / pages * 100%`, `role="progressbar"` with `aria-valuenow`/`min`/`max` and `aria-label`. A last page alone in a two-page view (odd total, e.g. page 3 of 3) reads `Page 3 of 3`.
10. **State hook for DPD-013:** `view.js` keeps `state = { id, page, step, pages }` and dispatches `CustomEvent('documents:modal-change', { detail: state })` on the dialog on every open and page change; DPD-013 fills `.documents-modal__body` from that event. A pure `pager.js` helper (`pagerItems( pages, current, step )`, `normalisePage()`, `visibleRange()`) holds the algorithm so it can be unit-tested with `node --test` (Node 24 is in DDEV) even though the theme has no JS runner.
11. **Accessibility:** `aria-labelledby` on the dialog = title id; focus moves to the Close button on open (hi-fi) and returns to the opener on close (`dialog` does this natively; verify); `Esc` closes natively; `Tab` stays inside. Pager buttons are real `<button type="button">`. Dimmed buttons use `aria-disabled` (kept focusable semantics consistent with the hi-fi) and the click handler ignores them.
12. **Page arrows (DPD-014):** two round 38px buttons inside the grey body, `top: 50%` with `translateY(-50%)`, `left: 18px` (Previous page) and `right: 18px` (Next page), frosted white like the hi-fi `.arrow.m`, `aria-label`s, chevron icons. They use the **same state and `turnPage()` as the footer pager** (two pages in the open-book view, one in single view, open-book starts on an odd page), so the pager and indicator update after each click (the ticket's "1-2 then 3-4 then back to 1-2" is covered by `pager.test.mjs`). `aria-disabled="true"` + 30% opacity on the first view (previous) and last view (next); with one page both are dimmed. **Visible only while hovering the body:** under `@media (hover: hover)` they are `opacity: 0` and become visible on `.documents-modal__body:hover`; they also appear on `:focus-visible` so keyboard users can find them, and on touch-only devices (no hover) they stay visible. Dimmed arrows stay at 30% when shown. The body now holds the two arrows and an empty `.documents-modal__stage[aria-live="polite"]` (the live region moved there) that DPD-013 fills.
13. **Not in this plan:** zoom, swipe, locked pages, sheets (all hi-fi features belonging to DPD-013/015/017+).

## Risks / open points
1. **Document has no software tools meta.** Recommended: add `cptdp_software_tools` here (plugin 0.17.0). Needs a yes/no before commit 1.
2. **Document has no description field.** Recommended: add excerpt support; alternative: derive from the editor content, or a new `cptdp_description` meta. Needs a decision before commit 1.
3. **Title style:** the ticket says bold serif larger; the hi-fi `.vtitlebox h2` is sans 22px/500. Plan follows the ticket (Georgia 700 26px); one line to flip to the hi-fi.
4. **Documents with no file:** ticket says Download is shown for every document, but a document can have only an embed URL (or nothing). Plan: embed fallback, then a disabled button. Confirm.
5. **Two-page view for every multi-page document.** There is no page orientation data (the hi-fi has `d.o`); the ticket only describes two-page and one-page. Landscape single-page mode is deferred to DPD-013 if needed.
6. **No shelf yet (DPD-016):** the whole-item click target and `data-document-id` wrapper is defined here via the contract in decision 3 and exercised through the TEMP fixture; DPD-016 must keep the attribute.
7. **Close alignment:** the X lives in the same flex row as Download (not absolutely positioned), so the two always share a centre line; if the header wraps they wrap together.
8. **Payload size:** all documents are inlined as JSON; fine for a portfolio. Switch to REST per click if the set grows past a few hundred.
9. **`<dialog>` support** is universal on current browsers; no fallback is planned.
10. **JS testing:** only the pure `pager.js` is covered automatically; DOM wiring is manual (no browser runner), as for the categories block.
