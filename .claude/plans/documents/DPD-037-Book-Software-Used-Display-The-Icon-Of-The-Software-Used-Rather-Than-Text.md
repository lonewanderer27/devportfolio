# Plan: Software used, display the icon of the software used rather than text (book, modal header and mobile Details sheet)

Ticket DPD-037 (Medium, User Interface), area *Book / Software Used*: *As a visitor, the software used for a document is shown as the icons of those tools, not as a line of names, everywhere the Documents page lists it: under the book on the shelf, in the document modal header and in the mobile Details sheet.*
Branch suggestion `feat/DPD-037-Software-Used-Icons`. **Theme only**, and it **depends on `DPB-033-Software-Tool-Icon-Store-The-Icon-Of-Each-Software-And-Populate-In-The-Database.md`** (the icons must be stored and seeded first). Builds on `DPD-016-Shelf-Grid.md` (the `software-tags` block), `DPD-009-010-011-012-014-015-Document-Modal.md` (the modal header), `DPD-023-Document-Modal-Mobile-Details-Sheet.md` (the Details sheet) and `DPD-034-Design-Redesign-According-To-Design-System.md` (the phone layout that hid the tags).

**This is a Documents page enhancement.** The three places below are all part of the one ticket, so a document's tools look the same wherever they appear. The shared `software-tags` block stays reusable for videos and collaterals; the modal and the sheet are document-only code.

**Out of scope:** the tool icon storage (DPB-033), a software filter (`DPD-035-Reusable-Checkbox-Filter.md` can reuse the same icons later), links from an icon to the tool's website, and the mobile Pages sheet (it shows no tools).

## Context (what the code does today)
- **Book (shelf item).** `devportfolio/software-tags` (`blocks/software-tags/`) is a reusable dynamic block (`usesContext: postId`, attribute `limit`, default 2). `render.php` calls `devportfolio_software_tool_names()` and prints each name as `li.software-tags__item`, separated by a gradient dot, plus a `+N` item and CSS that hides the extras at 480px and below. At 480px and below DPD-034 **hides the tags** (`.documents-item .software-tags { display: none }`), because three wrapped lines of text pushed the second row off the first phone screen.
- **Modal header (desktop).** The payload (`devportfolio_document_modal_payload()` in `functions.php`) carries `tools` as an array of names. `blocks/document-modal/view.js` `drawHeader()` turns each name into a `li` (`textContent`) in `ul.documents-modal__tags`, styled as small text separated by a gradient dot (`style.css`, `.documents-modal__tags`). The list is hidden when empty.
- **Mobile Details sheet.** `blocks/document-modal/details-sheet.js` `detailsModel()` (pure, tested with `node --test`) maps `doc.tools` to cleaned strings; the builder renders each as `li.documents-mobile__details-tool`, a grey text pill, in `ul.documents-mobile__details-tools`, hidden when empty. The sheet re-lays out in two columns when a phone is held sideways (CSS only).
- After DPB-033 each `software_tool` has an icon as its featured image, available through the plugin helper `cptdp_get_software_tool_icon( $tool_id )`.

## Key decisions
1. **One data shape for all three places.** A theme helper `devportfolio_software_tools( $post_id )` returns, in stored order and for published tools only, `array( array( 'id' => int, 'name' => string, 'icon' => array( 'url', 'width', 'height' ) | array() ), ... )`. The icon comes from `cptdp_get_software_tool_icon()` through `function_exists()` (the theme's existing pattern for plugin APIs); without the plugin or without an icon the `icon` array is empty. `devportfolio_software_tool_names()` stays (it is used elsewhere and by tests) and is rebuilt on top of the new helper.
2. **Payload.** `devportfolio_document_modal_payload()` keeps `tools` (names, for compatibility and the existing tests) and adds `toolItems`: `[ { "name": "Notion", "icon": { "url": "...", "width": 96, "height": 96 } | null } ]`. The JSON stays `</script>`-safe like the rest of the payload. URLs are the attachment URLs of the `cptdp-tool-icon` size.
3. **No icon, no problem.** A tool without an icon is drawn as **its name as text** in the same slot (the current look), in the book, the header and the sheet, so a half-populated database never shows an empty or broken slot.
4. **Accessibility is kept without text.** Every icon is an `<img>` with `alt` = the tool name (and `title` for the desktop hover tooltip). Lists keep their `ul` semantics, and the `+N` item has an `aria-label` ("3 more tools: A, B, C"). Contrast of a 1px ring against the page and the sheet is checked. There is no animation, so reduced motion has nothing to disable.
5. **Book (shelf item): one row of icons, never wrapping.** `software-tags` gets an attribute `display` (`icons` or `text`, default `icons`); `text` keeps today's markup so other callers and `tests/test-software-tags.php` do not change. Icons are 24px squares (28px from 1024px, 22px at 480px and below) with 8px gaps in a `flex-wrap: nowrap` row, on a white chip with a 1px `--wp--custom--edge` ring and 6px radius so a transparent logo reads on the dot grid. `limit` means "icons shown": **4 on tablet and desktop, 3 at 480px and below**, then `+N` (its `title` lists the hidden names). A 150px phone column fits 3 x 22px + 2 x 8px gaps + a `+N` of about 28px, about 110px.
6. **Phones get the tags back.** The DPD-034 phone hide rule is removed: the row is one line of about 30px under the 2-line description, so the "as many books as possible on the first screen" goal holds. Verify at 360, 375 and 390px, and trim the phone `info` padding if the second row moves by more than about 30px.
7. **Document modal header (desktop): icons only, with a tooltip.** The header has room and a mouse, so `ul.documents-modal__tags` becomes a row of 28px icon chips (same ring and radius as the book) with `title` and `alt` = the name; no dot separators and no text, and no "+N" (the header shows every tool, and wraps if there are many). `drawHeader()` builds each item with DOM APIs (`createElement`, `img.src`, `img.alt`, never `innerHTML`), and a tool without an icon renders its name as text in a small pill.
8. **Mobile Details sheet: icon and name per tool** (decision for the owner; recommended). Touch has no hover tooltip and the sheet is a reading surface with room, so each tool is a pill with a 24px icon followed by the name (`documents-mobile__details-tool`, grey `surface-alt` pill as today). If the owner prefers icons only, a single modifier class on the list (`documents-mobile__details-tools--icons-only`) hides the text visually (the name stays as `alt` and visually hidden text); the markup and tests do not change. Held sideways the two-column layout is unchanged.
9. **One pure helper for the JS side.** A new `blocks/document-modal/tool-items.js` (pure, no DOM, tested with `node --test` like `pager.js`, `mode.js` and `deeplink.js`) holds `toolItems( doc )`: it reads `doc.toolItems` (falling back to `doc.tools` strings, so an old payload still works), trims names, drops empties and duplicates, and accepts an icon only when its URL is `http`, `https` or a root-relative path and its width and height are positive numbers (clamped to 256). `view.js` and `details-sheet.js` (`detailsModel()` now returns `tools` as `{ name, icon }` objects) both use it, so the header and the sheet cannot drift apart.
10. **Performance.** At most 4 small images per book and the modal and sheet draw only the open document's tools. Icons are the 96x96 size shown at 22 to 28px, lazy-loaded with explicit width and height (no layout shift) and decoded asynchronously; the same 31 files are cached by the browser after first use.
11. **Tint (design decision, recommended: colour).** Icons are shown in brand colour. If the owner prefers the greyscale look of the rest of the page, `filter: grayscale(1)` with colour on hover (and in the modal) is a one-line change documented in the CSS comment, not shipped.
12. **Tests as specification.** `tests/test-software-tags.php` keeps asserting the `text` mode; new PHP tests cover the icon mode and the payload; new and updated node tests cover the helper and the sheet.
