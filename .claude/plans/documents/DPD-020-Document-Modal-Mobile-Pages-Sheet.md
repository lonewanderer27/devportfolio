## Ticket (verbatim intent)
**DPD-020, Modal - Mobile, Footer - Pages** (Medium, User Interface, depends on DPD-019; device width 700px or less; a document with at least 3 pages). When I tap **Pages** in the mobile footer I get a **bottom sheet over the dimmed viewer**:
- **Header:** title `Pages` (left); two small grouped icon buttons (right): image icon = **Gallery**, list icon = **List**. The active view's button is filled dark with a light icon, the other is outlined. The sheet opens in **Gallery**.
- **Gallery:** at most a 3x3 grid (3 columns) of page thumbnails; each is a small portrait page with its number in the centre; the current page has a thick dark outline.
- **List (one row per page):** leading square with the page number (thick dark outline for the current page); content = page title/name (bold), **the number is not repeated as text**; ending = `current` in lighter text right after the name of the current page (`Hotels · current`); thin lines between rows.

## Goal
Make the existing `Pages` buttons do something. Both already exist and already emit `documents:mobile-pages` (footer `.documents-mobile__pages` in `mobile.js`, and the round Pages button from `makeDetails()` in `mobile-viewer.js`, shown in touch landscape). Nothing listens yet. Build the sheet, open it from that event, jump to the chosen page.

## Context (what exists, do not rebuild)
- **Event, not a new button:** `mobile.js` emits `documents:mobile-pages` with `{ id, page, pages, step }`. The sheet is wired in `mobile.js` (which owns the page state), not in `mobile-viewer.js`.
- **Jump:** `setPage( n )` in `mobile.js` normalises, redraws the footer, emits `documents:mobile-change` and calls `viewer.goTo()`. Works for stored images, pdf.js, and the native PowerPoint canvas.
- **Visible pages:** `visibleRange( page, pages, step )` in `pager.js` (step 2 in a mobile spread). The current marker follows it.
- **Visibility today:** the Pages buttons show for `pages >= 2` (`drawFooter()`); native grid/scroller documents (xlsx, docx) report one piece, so they never show it. Unchanged. The ticket's "at least 3 pages" is the case it was written for, not a rule (same call as DPD-019 decision 2).
- **Sheet chrome to match:** `.documents-mobile__details-panel` (surface, line, radius tokens `--dm-*`), 38px round buttons, `routing.js` media queries (no new one), `documents-mobile-up` animation, `prefers-reduced-motion` handling.
- **Strings:** `devportfolio_document_mobile_strings()` -> `data-mobile-strings`; units (`page`/`slide`) from `data-units`.
- **Data contract from DPB-030 (names) and DPB-031 (thumbs)** (the only thing this ticket needs from the backend): `cptdp_get_document_pages()` returns `names` (array, one string per page, `''` where none, or `[]`) and `thumbs` (array of small webp URLs, ~240px wide, one per page, or `[]` when any is missing). Until DPB-030 ships, or for documents not yet regenerated, both are `[]` and the sheet shows numbered blank tiles and unit-word rows. Names: PDF/Word chapter titles from bookmarks/headings, Excel sheet names, PowerPoint blank. The wireframe (`pn: ['Trip summary','Flights','Hotels','Transfers']`) used placeholders. Locks (`lk`) in that wireframe are **out of scope**.

| Aspect | Behaviour |
|---|---|
| Container | A bottom sheet **inside the mobile `<dialog>`** (not a second dialog): `div.documents-mobile__sheet` plus a dim layer `.documents-mobile__dim` over the viewer. Stays inside the dialog so the top layer, focus trap, Back handling and the DPD-032 deeplink are untouched. |
| Open | Tap `Pages` (footer or round button). Slides up 0.24s (none with reduced motion). Opens in **Gallery** the first time; after that it opens in the **view this document was last shown in**, scrolled to **where that view was left** (owner, per document, in memory for the life of the page, surviving closing the viewer; a view never scrolled before is centred on the current page). Opening hides the round buttons and closes the details panel. |
| Close | Tap the dim layer, tap or **drag down** the grab handle or the title row (past 96px, or a quick flick, closes; otherwise it springs back), or Esc; choosing a page. Esc closes the sheet only (intercept the dialog's `cancel` while the sheet is open), a second Esc closes the viewer. Closing the document, rotating across the dialog swap, or `reset()` also closes it. Focus returns to the control that opened it. |
| Header | `Pages` (left, 13px bold, `<h3 id>`). Right: `role="group"` of two 28x24 icon buttons with `aria-pressed` and labels `Gallery view` / `List view`. Active = filled `--dm-ink` with light icon; other = outlined. Icons copied from the hi-fi (`#vtGrid`, `#vtList`). Switching is instant; each view keeps its own scroll position and comes back to it. |
| Gallery | `display: grid; grid-template-columns: repeat(3, 1fr)`. **At most 3x3 visible**: the grid area is capped at three rows and scrolls for more pages (documents of 24 pages are the norm). Each tile: portrait page shape showing the **real page thumbnail** (`thumbs`, from DPB-031) with the number in a small chip centred at the bottom (a centred number would hide the page); with no thumbnail (documents not yet regenerated, or no thumbs) the number sits in the centre of a blank page, as in the ticket. Thick dark outline (`3px --dm-ink`) on the current page. Tile = `<button>`, `aria-label="Page 3"`, `aria-current="page"` on current. |
| List | One `<button role=...>` row per page, thin `--dm-line` separators. Leading 2:3-ish square with the number (thick outline when current); then the **name in bold**; the current row appends ` · current` in `--dm-subtle` weight 400 straight after the name (a `<span>`, text from the strings, not CSS-only, so screen readers get it). The number is **not** repeated in the name column or `aria-label` text beyond the accessible name `Page 3, Hotels`. |
| Thumbnail loading | **Only the thumbnails you can see are fetched** (owner), however long the document. No `src` is set at build time: each tile holds its URL in `data-src` and a reserved box (fixed aspect ratio from the document's `ratio`, so nothing jumps). One `IntersectionObserver` rooted on the gallery's own scroll area with `rootMargin: 0 0 1 row` (about one row ahead, never more) sets `src` when a tile enters and stops observing it; native `loading="lazy"` is **not** relied on because browsers fetch well beyond the viewport (Chrome about 1250px+ ahead), which in a small 3x3 view could pull dozens of images. Result on open: at most the 9 visible tiles plus the next row (about 12 requests), then roughly one row more per scroll step. The **List view requests no images at all**; switching to Gallery starts observing then. Opening the sheet at page 150 scrolls the current tile into view **first**, then observes, so pages 1 to 149 are never fetched. A fast fling past tiles never loads the ones skipped (a tile that left the view before its image started is not requested; once started it finishes). No prefetch, no preload hints, `decoding="async"`, and one load is cached by the browser for the rest of the visit. |
| Large documents | The tile boxes are cheap (no image), so 24 or 300 pages build instantly; above **150 pages** the gallery is built in chunks of 60 as the scroll nears the end (windowing), so the DOM stays small. The list view does the same with rows. |
| Selecting | Tap a tile or row -> `setPage( n )`, sheet closes, viewer turns. In a spread, an even page jumps to the spread that holds it (existing `normalisePage`). |
| Current marker | **Owner decision: both visible pages of a spread are marked** (`visibleRange()`); the list shows `current` on each. |
| Updates while open | The sheet is modal over the viewer, so the page cannot change under it; it is rebuilt on open only. Resize/rotation closes it. |
| Landscape touch (<= 520px high) | Same sheet, `max-height: 80%` of the dialog, gallery still 3 columns (smaller tiles), list scrolls. The round Pages button hides while it is open. |
| One piece / native grid / scroller | Not reachable (buttons hidden). |
| Names missing | A row with no name (every PowerPoint slide, `.xls`, a PDF without bookmarks, a page no bookmark points at) shows the unit word only (`Page`, `Slide`, `Sheet`), never the number again. |
| Back button | **Owner decision:** with the sheet open, Back closes **only the sheet**; a second Back closes the viewer (Decision 5). |

## Decisions and rationale
1. **Names and thumbnails are not made here.** They come from DPB-030 (names) and DPB-031 (thumbnails) through the payload (`pageNames`, `thumbs`); this ticket only displays them and falls back cleanly when they are empty (numbered tiles, `Page`/`Slide`/`Sheet` rows). Tiles load their image only when visible (see "Thumbnail loading": `data-src` plus an `IntersectionObserver`, not native `loading="lazy"`) and honour the document's `cropBottom` like the book. List-view leading squares stay numbered squares (ticket).
2. **Real thumbnails, not the 1400px page images**, so a 24-page gallery stays light on a phone; if `thumbs` is empty the sheet does **not** fall back to the full-size images (it uses numbered tiles).
3. **One sheet inside the existing dialog**, not a stacked `<dialog>`: avoids Esc/Back/focus-trap fights and the swap logic of `routing.js`.
4. **A module of its own**, `pages-sheet.js`, with a **pure model** (`pagesModel( { pages, step, page, names, unit, strings } )` -> `[ { n, name, current, label } ]`) so the logic runs under `node --test`; the DOM builder is a thin layer. `mobile.js` only wires it (event in, `setPage` out), keeping to the "shared pieces, extend rather than copy" rule.
5. **Back closes only the sheet (owner).** Opening the sheet `pushState`s one entry (like the viewer does), so the phone Back pops it and closes the sheet; a second Back closes the viewer. Closing the sheet by tap, Esc or choosing a page uses `history.back()` when the sheet added the entry, mirroring the DPD-032 rule for the viewer. This **must be taught to `deeplink.js`/`view.js`** (they currently assume one entry per open document): a `documents:mobile-pages` entry carries a marker in `history.state`, `popstate` closes the sheet only if the marker is being left, and closing the viewer while the sheet is open removes both entries. Cover the pure part (`deeplink.js`) with `node --test`.

## Performance (beyond visible-only loading)
- **Load the sheet code only when it is used.** `pages-sheet.js` is pulled in with `import()` on the **first** tap of `Pages` (a script module cached afterwards), not at page load or when the modal opens; most visitors never open it. The sheet CSS lives in the existing `style.css` (no extra request).
- **Build once per document, update in place.** The tiles and rows are created the first time the sheet opens for a document and **kept**; reopening only moves the `current` markers and the outline (class toggles on at most the old and new tiles) and scrolls to the current page. Loaded thumbnails stay loaded, nothing is rebuilt or re-observed, and reopening is instant. The cache is dropped when another document opens or the viewer closes.
- **One listener, not hundreds:** a single delegated `click` on the gallery and on the list (`event.target.closest( '[data-page]' )`), passive scroll/observer, no per-tile handlers.
- **Cheap layout:** tile and row boxes use `aspect-ratio` from the document's `ratio` (and the thumbnail's width and height), `content-visibility: auto` with `contain-intrinsic-size` on rows and tiles outside the view (long documents skip their layout and paint), `contain: layout paint` on the sheet body, `overscroll-behavior: contain`, and only `transform`/`opacity` are animated (`will-change` only while the sheet is sliding).
- **Compact payload.** The modal payload carries every published document, so it stays small: `thumbs` is sent as a **descriptor** `{ base, ext, count, width, height }` (the URL of page *n* is `base + 't-' + pad( n, 3 ) + ext`, built in JS; falls back to a plain URL list if the PHP check finds URLs that do not follow the pattern), `pageNames` as **ranges** `[ [ first_page, title ], ... ]` expanded in JS, and **neither key at all** for a document without them. The page count and `ratio` already in the payload are reused.
- **Respect data saver.** With `navigator.connection.saveData` on (the gate `capability.js` already reads), the gallery shows the numbered blank tiles and loads **no** thumbnails (tapping a tile still jumps to the page); the list view is unaffected.
- **Be kind to the network on close:** pending thumbnail requests that have not completed when the sheet closes are cancelled (their `src` is cleared), and the observer is disconnected; no prefetching of anything, ever (no `<link rel=preload>`, no hover prefetch).
- **Priority:** thumbnail images use `decoding="async"` and `fetchpriority="low"` so they never compete with the page the visitor came to read; the page being viewed always wins.
- Thumbnail files are immutable and cached for a year (DPB-031), so a thumbnail is downloaded at most once per visitor across visits.

## Accessibility
Sheet `role="dialog"`, `aria-modal="true"`, `aria-labelledby` the title; focus moves to the active view button on open (or the current page tile) and returns on close; Tab stays inside the sheet while open (the rest of the dialog gets `inert`); tiles/rows are buttons with `aria-current="page"`; the toggle is a `role="group"` with `aria-pressed`; 38px minimum touch targets for rows (tiles are larger); `current` is real text; contrast follows the `--dm-*` tokens.

## Risks and open points
1. **Depends on DPB-030 and DPB-031 for real content.** Until they ship and documents are backfilled (`ddev wp cptdp pages names --all` and `pages thumbs --all`, both fast and without reconversion; a Word document needs `pages generate <id> --force` once), every sheet shows numbered tiles and unit-word rows. Acceptable to merge first; the sheet is complete either way.
2. **Chapter names repeat** over several pages (what the file offers, DPB-030 decision); the list may show the same name on consecutive rows. Fine.
3. **Visible-only loading** (see the behaviour table): the observer must be created on the right scroll container (the sheet body, not the dialog), disconnected on close and on switching to List, and must ignore the tiles of a hidden view; test the open-at-page-150 case and a fast scroll on a real phone, and count requests in the network panel (target: about 12 on open for a 300-page document, none in List view).
4. **Spread + jump:** choosing the second page of a spread lands on its spread; check the "current" marking and `normalisePage` agree on both pages.
5. **Esc interception and history:** must not break the DPD-032 close bookkeeping (`close` event still fires only when the dialog really closes). Cover with a browser check.
6. **Native PowerPoint canvas:** `goTo()` while a slide is drawing (`isTurning()`) must not queue duplicate renders; the sheet closes first, then turns.
7. **iOS Safari:** dim layer + `inert` on a `<dialog>` and `overscroll-behavior: contain` on the sheet body need a real-phone check; no browser runner exists in the repo (headless Chrome with puppeteer-core at 390x844 and 844x390, as in DPD-026/030).

**Differences from the plan**
- **History code lives in `sheet-back.js`**, not `mobile.js`, because an existing test requires `mobile.js` to contain no `history.`; the file name avoids `history.` for the same reason.
- **`visibleTiles()` is the fallback path**, used only when `IntersectionObserver` is missing; normal loading uses one observer with about one row ahead.
- **Payload:** `thumbs` is a `{ base, ext, count, width, height }` descriptor and `pageNames` is ranges, both omitted when empty (as planned). The plugin returns names expanded (`names`) and as ranges (`name_ranges`); the theme packs the expanded list into ranges itself.
- **`close( true )`** closes the sheet without calling `onClose` or restoring focus (used by the history code and `reset()`).
- **The sheet remembers, per document, the view last used and each view's scroll position** (`createSheetMemory()`), in memory only, kept across closing and reopening the viewer, dropped on a page reload. This replaces the plan's "always opens in Gallery"; a view never scrolled before is centred on the current page; a long document is rebuilt as far as it was scrolled.
- **The handle (and the title row) can be dragged down to dismiss** (pointer events with capture): 96px closes, a flick of 0.6 px/ms after 24px closes, otherwise it springs back; a tap or Enter/Space on the handle still closes; the Gallery and List buttons never start a drag; reduced motion skips the animation. `touch-action: none` on the handle and title row.
- **History and the Interactivity Router (found by testing in a browser):** WordPress's Interactivity Router answers every `popstate` and calls `location.reload()` for a URL it has not cached (it caches only the URL the page loaded with). The first tile tap pops the sheet's entry back to `?document_slug=...`, so the page reloaded and the modal flickered and re-opened; the category filter script also started a page-wide View Transition on every popstate. Fixes: `sheet-back.js` stops the event for the sheet's own moves, the modal's popstate handler in `view.js` stops it whenever it opens or closes the modal (and on the sheet's stale entry), the category filter does nothing unless the category changed and keeps a real category change from the router. **Listeners run in the order they were added** (capture did not run first on `window` in Chrome here), so the three are added as their scripts run, before the router is imported. This also removed the reload on Forward after closing the viewer, and on Forward through a category change.
