**Spreadsheets (v0.21.0, DPB-027):** a document's file may also be an `.xlsx`, `.xls` or `.ods` (`CPTDP_Page_Store::SPREADSHEET_MIMES`, `is_spreadsheet_kind()`, `is_office_kind()` = presentation or spreadsheet, which the scheduler, converter, REST routes, manifest marks and no-trim rule now test). Same pipeline and the same `CPTDP_Pptx_Converter::to_pdf()` (one soffice at a time, throwaway folder and profile, 120 s), with Calc's export filter from `CPTDP_Xlsx_Converter::export_filter()`: **one page per sheet** (`pdf:calc_pdf_Export:{"SinglePageSheets":...}`, filter `cptdp_xlsx_single_page_sheets`). Server only, never `needs_browser`; the browser upload routes still answer 400 `cptdp_pptx_server_only` (the code kept for compatibility). Without LibreOffice or Calc a spreadsheet is `failed` with a PDF recommendation, except a `.xlsx` with `native_xlsx` ticked (status `none`). The shared Office pieces live in `includes/post-types/document-office.php`: `cptdp_office_warning()` / `cptdp_office_warnings()` (dispatch by kind), `cptdp_office_warning_html()` (the warning chrome: first paragraph plus the Native viewer link paragraph for users who can `manage_options`), `cptdp_native_viewer_enabled( $kind )` (the setting for a kind that has a switch; the scheduler uses it to leave a `.pptx`/`.xlsx` at status `none` on a host without LibreOffice) and `cptdp_native_office_url()` (kind, setting and size rules; `cptdp_document_native_pptx_url()` and `cptdp_document_native_xlsx_url()` are one-line wrappers). Only the wording lives in `document-presentations.php` (`cptdp_pptx_warning()`) and `includes/post-types/document-spreadsheets.php` (`cptdp_xlsx_warning()`); they warn in the media picker (the localized `pptxWarnings` now holds every Office kind), the Document File and Page images boxes and once after saving; the warning says everything on visible sheets is published, and for `.xlsx` and administrators links to the Native viewer section. ```bash

Data lives in `wp-content/plugins/custom-post-types-dp/data/seeders/<name>.csv` (edit the CSV, not the code). Seeders are idempotent: an item whose title already exists (any status, incl. Trash) is skipped, never modified. Content, not structure: never run on activation. The whole CSV is validated before any write. Thumbnails are added manually in wp-admin. `ddev snapshot` before a real run on a DB you care about.

Adding a seeder: (1) CSV in `data/seeders/<name>.csv` with a header row incl. `title`; (2) `includes/seeders/<name>.php` that adds its entry to the `cptdp_seeders` filter and defines the callback (copy `software-tools.php`; use `cptdp_seed_read_csv()` and `cptdp_seed_title_exists()`); (3) `tests/seeders/test-<name>.php` extending `CPTDP_Seeder_Test_Case` (implement `seeder_name()`, add column-mapping assertions). `list` is a reserved seeder name. `--all` order: `aspect-ratios`, `collateral-categories`, `document-categories`, `services`, `software-tools`, `statistics`, `video-categories`, `videos`, `collaterals`, `documents` (the videos seeder needs both term seeders first; `collaterals` needs `collateral-categories` and `software-tools`, and `documents` needs `document-categories` and `software-tools`, so their files are `includes/seeders/z-collaterals.php` and `z-documents.php` to be required last: seeders run in file-name order). The `documents` seeder creates 8 published documents (excerpt = description, `cptdp_filetype`, `cptdp_total_pages`, `cptdp_author`, one `document_category`, `cptdp_software_tools` from `|`-separated tool titles; no uploaded files, no cover style), `ddev wp cptdp seed documents`. The `collaterals` seeder creates 6 published collaterals (description in `post_content`, since the type has no excerpt; `cptdp_paper_size`, `cptdp_total_pages`, `cptdp_highlight`, one `collateral_category`, `cptdp_software_tools` from `|`-separated tool titles, `cptdp_post_statistics` from `|`-separated `label:value` pairs split on the first colon; orientation is only a `paper_size` label such as `A4 Landscape`; no uploaded files or thumbnails), `ddev wp cptdp seed collaterals`. Term seeders (`aspect-ratios`, `collateral-categories`, `document-categories`, `video-categories`) recreate a term deleted in wp-admin, since terms have no Trash; WP always recreates a taxonomy's default term (`16x9`) on the next request.

### Tests (PHPUnit 9 + `WP_UnitTestCase`, two suites)

There are two independent suites: **plugin** (`custom-post-types-dp`, the content model) and **theme** (`devportfolio`, the main navigation). Both share one PHPUnit install (the plugin's `vendor/`), one WP test library and one test DB, so the setup is done once. Both run against the dedicated DB `wordpress_test` (table prefix `wptests_`). The WP test library **drops every table in its DB**, so never point it at the dev DB `db`; both `tests/bootstrap.php` files and the plugin's `bin/install-wp-tests.sh` refuse that.

```bash
# one-time (and after `ddev restart`/rebuild: the test lib lives in the container's /tmp)
ddev composer --working-dir=wp-content/plugins/custom-post-types-dp install
ddev exec "bash wp-content/plugins/custom-post-types-dp/bin/install-wp-tests.sh"

# plugin suite
ddev exec --dir=/var/www/html/wp-content/plugins/custom-post-types-dp vendor/bin/phpunit
# filters: --filter CPTDP_Test_Video | --group settings | --testdox

# theme suite (runner is the plugin's PHPUnit; the theme has no Composer deps of its own)
ddev exec --dir=/var/www/html/wp-content/themes/devportfolio ../../plugins/custom-post-types-dp/vendor/bin/phpunit
# filters: --filter Devportfolio_Test_Navigation | --group theme | --testdox
```

Run both before a PR that touches the plugin or the theme: a plugin change (e.g. a CPT's archive slug) can break theme tests. `ddev composer ... test` also works for the plugin but hides PHPUnit's output on failure; prefer the `ddev exec` form. Expected totals today: plugin 829 tests (12 skipped), theme 388 tests, modal JS 153 tests and collateral grid JS 17 tests (`node --test`), all passing (the two earlier `Devportfolio_Test_Navigation` Services-link failures are fixed, so there are no known failures).

**Page names and thumbnails (v0.23.0, DPB-030/031):** when a document's pages are made, the plugin also makes a **name per page** and a **small thumbnail per page**, both stored with the page set and returned by `cptdp_get_document_pages()` as `names` (one string per page, `''` where none, `[]` when the file has none), `name_ranges` (`[ [ first_page, title ], ... ]`), `thumbs` (URLs, `[]` when any is missing, so a half set is never used), `thumb_width`, `thumb_height`. **Names** (`CPTDP_Page_Outline`, `includes/documents/class-page-outline.php`): a small read-only pure-PHP PDF reader (no Ghostscript or Imagick outline dump exists; it scans `N G obj`, reads the catalog, page tree, outline, name trees and object streams, bounded by `cptdp_outline_max_bytes` 50 MB, `cptdp_outline_timeout` 15 s and 2000 entries, gives nothing for encrypted or malformed files, and never fails a conversion) maps bookmarks to pages; a bookmark names its page and every page after it until the next one, the deepest bookmark starting on or before the page wins. **PDF** from the PDF itself, **Word** from the temporary PDF LibreOffice Writer writes (its filter now sets `ExportBookmarks`, so headings become bookmarks), **Excel** from `CPTDP_Xlsx_Converter::sheet_names()` (visible sheets only, from `xl/workbook.xml` or the ODS `content.xml`, trusted only when the count equals the page count; `.xls` has none), **PowerPoint** blank. Stored in the manifest as `page_names` ranges (omitted when none). **Thumbnails** (`CPTDP_Page_Thumbs`): `t-001.webp` beside `p-001.webp`, 240px wide, webp quality 65 (45 when over 20 KB), made from the page already in memory (Ghostscript sets, and sets whose in-memory thumbnails failed, get them from the stored images), always from the uncropped page; manifest `thumb_width`/`thumb_height`. A set without thumbnails is valid and is not re-queued. Browser-made sets: the admin script (`assets/admin-document-pages.js`) draws and uploads each thumbnail (`POST .../pages/<n>?thumb=1`, at most 280px wide and 100 KB) and sends `pageNames` from `pdf.getOutline()` on `finish`; the finish step keeps thumbnails only when the whole set is valid (else the server makes them if it has Imagick). WP-CLI backfills without converting again: `ddev wp cptdp pages thumbs [<id>|--all] [--force]` (resizes the stored page images), `ddev wp cptdp pages names [<id>|--all]` (PDF and Excel from the stored source; a Word document needs `pages generate <id> --force` once because its converted PDF is not kept); `pages status` has `names` and `thumbs` columns. **Admin:** the Documents list Thumbnail column shows the featured image if there is one, else the page-1 thumbnail (`cptdp_document_admin_thumb()` / `cptdp_document_admin_thumb_html()`, the same file the mobile Pages sheet draws for page 1; a set made before thumbnails falls back to the first stored page image scaled by CSS), lazy and low priority with a reserved box; the column is 90px wide; the Page images box on the edit screen shows it too. A featured image is made from page 1 when a set becomes ready (DPC-023, see *Featured image from page 1* below). Thumbnail URLs are immutable (the folder name carries the file fingerprint), so the host can cache `uploads/cptdp-pages/**.webp` for a year (`Cache-Control: public, max-age=31536000, immutable`); this is a host setting, not set by the plugin.

an image source answers 400 `cptdp_server_only` on `start`/`<n>`/`finish` (Office keeps `cptdp_pptx_server_only`). **Admin:** the Collaterals list has the Page images column and the page-1 Thumbnail fallback (one shared `cptdp_pages_status_cell()` for both lists); the Page images meta box (`add_meta_boxes`, every registered type) and the needs-browser list notice work on both. **WP-CLI:** `ddev wp cptdp pages generate|clear|status|recrop|thumbs|names|featured` take a document or collateral ID; **Shared page image settings (DPC-023):** Settings -> Documents has a section **"Page images (Documents and Brand Collaterals)"** (`cptdp_documents_page_images`, anchor `#cptdp-page-images`) holding `pages_mode`, `trim_bottom` and `featured_from_page`; its intro says they apply to both pages, and the "Documents" section keeps only the book title ("Options for the Documents page only."). **Featured image from page 1 (DPC-023, documents and collaterals):** `CPTDP_Page_Featured` (`includes/documents/class-page-featured.php`). When `save_manifest()` leaves a set `ready` (server or browser producer) and the post has no featured image, page 1 (`p-001` read from the validated folder, uncropped, copied and added with `media_handle_sideload()` so WordPress makes its sub-sizes; file `<slug>-page-1.<ext>`, parent = the post) becomes the featured image. Ownership: post meta `cptdp_featured_generated` (not in REST) names it; the attachment carries `_cptdp_generated_for` (the post) and `_cptdp_generated_from` (the set folder), so the same set never makes a second copy. **An image an editor chose is never replaced or deleted.** A new file keeps the old generated image until the new set is ready, then swaps it (the old attachment is deleted). Removing the file deletes ours while it is still the featured image; deleting the post deletes ours; an editor deleting ours in Media clears the record. A failure is written to `cptdp_document_pages_error` prefixed `Featured image: ` and never changes the page status. Switch: `featured_from_page` (default **on**; off keeps the images already made). Existing documents get one on their next conversion or with the backfill `ddev wp cptdp pages featured [<id>|--all] [--post_type=...] [--force]` (`--force` remakes ours only). Tests: `tests/collaterals/test-page-featured.php` (`CPTDP_Test_Page_Featured`, every case for both types) and the settings cases in `tests/settings/test-documents.php`.
