### Seeders

```bash
ddev wp cptdp seed list                      # registered seeders
ddev wp cptdp seed software-tools            # run one
ddev wp cptdp seed --all --dry-run           # preview everything, writes nothing
ddev wp cptdp seed --all                     # run all, in registration order
```

Data lives in `wp-content/plugins/custom-post-types-dp/data/seeders/<name>.csv` (edit the CSV, not the code). Seeders are idempotent: an item whose title already exists (any status, incl. Trash) is skipped, never modified. Content, not structure: never run on activation. The whole CSV is validated before any write. Thumbnails are added manually in wp-admin. `ddev snapshot` before a real run on a DB you care about.

Adding a seeder: (1) CSV in `data/seeders/<name>.csv` with a header row incl. `title`; (2) `includes/seeders/<name>.php` that adds its entry to the `cptdp_seeders` filter and defines the callback (copy `software-tools.php`; use `cptdp_seed_read_csv()` and `cptdp_seed_title_exists()`); (3) `tests/seeders/test-<name>.php` extending `CPTDP_Seeder_Test_Case` (implement `seeder_name()`, add column-mapping assertions). `list` is a reserved seeder name. `--all` order: `aspect-ratios`, `document-categories`, `services`, `software-tools`, `statistics`, `video-categories`, `videos`, `documents` (the videos seeder needs both term seeders first; `documents` needs `document-categories` and `software-tools`, so its file is `includes/seeders/z-documents.php` to be required last: seeders run in file-name order). The `documents` seeder creates 8 published documents (excerpt = description, `cptdp_filetype`, `cptdp_total_pages`, `cptdp_author`, one `document_category`, `cptdp_software_tools` from `|`-separated tool titles; no uploaded files, no cover style), `ddev wp cptdp seed documents`. Term seeders (`aspect-ratios`, `document-categories`, `video-categories`) recreate a term deleted in wp-admin, since terms have no Trash; WP always recreates a taxonomy's default term (`16x9`) on the next request.

### Tests (PHPUnit 9 + `WP_UnitTestCase`, two suites)

There are two independent suites: **plugin** (`custom-post-types-dp`, the content model) and **theme** (`devportfolio`, the main navigation). Both share one PHPUnit install (the plugin's `vendor/`), one WP test library and one test DB, so the setup is done once. Both run against the dedicated DB `wordpress_test` (table prefix `wptests_`). The WP test library **drops every table in its DB**, so never point it at the dev DB `db`; both `tests/bootstrap.php` files and the plugin's `bin/install-wp-tests.sh` refuse that.

```bash
# one-time (and after `ddev restart`/rebuild: the test lib lives in the container's /tmp)
ddev composer --working-dir=wp-content/plugins/custom-post-types-dp install
ddev exec "bash wp-content/plugins/custom-post-types-dp/bin/install-wp-tests.sh"

# plugin suite
ddev exec --dir=/var/www/html/wp-content/plugins/custom-post-types-dp vendor/bin/phpunit
# filters: --filter CPTDP_Test_Video | --group settings | --testdox

# theme suite (runner is the plugin's PHPUnit; the theme has no Composer deps of its own)
ddev exec --dir=/var/www/html/wp-content/themes/devportfolio ../../plugins/custom-post-types-dp/vendor/bin/phpunit
# filters: --filter Devportfolio_Test_Navigation | --group theme | --testdox
```

Run both before a PR that touches the plugin or the theme: a plugin change (e.g. a CPT's archive slug) can break theme tests. `ddev composer ... test` also works for the plugin but hides PHPUnit's output on failure; prefer the `ddev exec` form. Expected totals today: plugin 458 tests (12 skipped), theme 136 tests (2 known failures in `Devportfolio_Test_Navigation`: the Services link resolves to `/#services` instead of the `service` archive; present on `main` before the document book work).

#### Plugin suite (`wp-content/plugins/custom-post-types-dp/tests/`)

Config `phpunit.xml.dist`, dev deps in the plugin's `composer.json`, `vendor/` git-ignored. Layout: shared base classes `tests/class-cptdp-*-test-case.php` (`CPTDP_CPT_Test_Case` for registration/columns/order/archive, `CPTDP_Media_CPT_Test_Case` for the video/document/collateral file+URL+statistics+save+REST pattern); one `test-*.php` per module under `tests/post-types/`, `tests/taxonomies/`, `tests/settings/`, `tests/seeders/`, plus `tests/test-loader.php`. A new CPT = a new test class extending the matching base and implementing its `expected*()` methods.

Gotchas: `WP_UnitTestCase` unregisters all meta after every test and wipes terms after bootstrap (options survive), so `CPTDP_Test_Case::set_up()` re-runs `cptdp_register_post_types`, and the aspect ratio tests re-seed. Core only assigns default terms when the current user can assign terms. Bootstrap forces `flush_rewrite_rules_hard` off so tests never write `.htaccess`.

New theme behaviour (a nav link, a template, a filter) = a new `tests/test-*.php` in the theme, not in the plugin. New plugin behaviour = the plugin suite.

## Theme architecture (`wp-content/themes/devportfolio/`)

Block (FSE) theme, intentionally tiny (no patterns, style variations, fonts, images or build step). Design lives in data, not PHP, and follows the lo-fi wireframes: greyscale (palette `base` #fff, `contrast` #222, `mid` #8a8a8a, `line` #c9c9c9, `fill` #eee), system sans font plus Georgia serif, 14px body, h3 as the 34px/800 page title, 1040px content width.
- `theme.json` — palette, typography, spacing, layout, global and block styles (incl. main navigation active-link style)
- `templates/` — `index`, `archive`, `search`, `single`, `page`, `404`, `archive-document` (Documents page: `<h3>Documents</h3>` plus empty `documents-page__content` container for the category buttons and shelf)
- `parts/header.html` — main navigation, 7 inline links (Home, Services, Documents, Videos, Collaterals, Testimonials, Contact) with root-relative URLs, centred, core mobile overlay; `parts/footer.html` — site title
- `functions.php` — one filter: resolves nav links (post type archives via `get_post_type_archive_link()`, others via `home_url()`) so core marks the current archive link with `aria-current` and flags Home on the front page
- `blocks/document-categories/` — dynamic block `devportfolio/document-categories` (DPD-002/003), registered in `functions.php` on `init`: `block.json`, `render.php`, `style.css`, `view.js`. Sits in `archive-document.html` under the title. "All" is synthetic (always first, never stored, `data-filter=""`, `aria-pressed="true"` by default); then one `<button>` per `document_category` term in name order (the DPD-007 seeded order), empty terms included, `data-filter` = term slug. `view.js` keeps one pill active and filters in place. The active category lives in the URL as `?category=<slug>` (All = no param): `pushState` on click, `popstate` re-applies on Back/Forward, `render.php` marks the matching pill pressed on first paint, and an unknown slug falls back to All (bad param cleaned with `replaceState`). Switches run inside `document.startViewTransition()` so the pill group (`view-transition-name: documents-categories`) fades in 0.2s; the root transition is disabled, and unsupported browsers or `prefers-reduced-motion: reduce` apply the change instantly. Shelf contract for DPD-016: shelf `[data-documents-shelf]`, each item `data-document-categories="slug slug"` (direct child of the shelf), planks `[data-shelf-plank]` are owned by the script (rebuilt after every filter and resize, one per row of grid columns). Mobile (<=820px): pills are one sticky, horizontally scrolling row (sticks at `top: 0`; the header part is not sticky).
- `blocks/document-book/` — dynamic block `devportfolio/document-book` (DPD-005/006/008), registered in `functions.php` next to the categories block: `block.json` (`usesContext: ["postId"]`), `render.php`, `style.css`. Renders the **cover only** (`div.documents-book[data-cover-style]`): `__cat` (first `document_category` term by name, empty span if none), `__ttl` (title; the short ornament line is its `::after`), `__ft` holding `__format` (`devportfolio_document_format_label()`: `PDF · 24 pp`, `1 p` for one page, parts dropped when missing) and `__owner` (`DAVE`). No status tag, description or tags on the cover; renders nothing for non-`document` posts. Cover style comes from post meta `cptdp_cover_style` (assumed to be provided by DPD-004; not registered by the plugin yet), whitelisted by `devportfolio_sanitize_cover_style()` against `devportfolio_cover_styles()` (`midnight`, `pinstripe`, `horizon`, `split-sky`, `dot-grid`, `two-tone`), unknown or missing = `midnight`. 2:3 cover following `.claude/plans/documents/documents-hifi-wireframe`: fixed light-mode `--book-*` tokens from `.claude/plans/design-system.html`, each style sets `--cv` / `--ct` / `--cat-c` (Midnight, Horizon, Split Sky and Two-Tone are dark with white text; Pinstripe and Dot Grid are light with dark text) and its pattern in the `__pat` layer (`<i aria-hidden>`, first child); only Horizon carries the gradient (the sun). 16px spine and a dashed stitch inset 8px top and bottom; at `max-width: 820px` the smaller two-column sizes apply. Motion is CSS only: hover (`@media (hover: hover)`) lifts 6px, tilts 1deg and deepens the flat shadow over 260ms; `:active` scales to 0.985 (what a tap shows); reduced motion disables both. The cover is not interactive: the shelf item (DPD-016) wraps it in the button/link and owns focus and click.
- `blocks/document-shelf/` — dynamic block `devportfolio/document-shelf` (DPD-016), registered in `functions.php`, placed after the categories block in `archive-document.html`. `render.php` outputs `div.documents-shelf[data-documents-shelf]` with one `article.documents-item[data-document-categories]` per published document (menu order, then title; the block renders nothing without documents): the `document-book` cover, then `__info` with the title (`h3` holding the one `button.documents-item__open[data-document-id]`, whose `::after` covers the whole item so the item opens the modal), the description (`devportfolio_document_description()`, omitted when empty) and the software tags (the reusable `devportfolio/software-tags` block, rendered with the item's `postId`). Tags are text separated by a gradient dot (hi-fi `.tags`, same as the modal header); a full-width dot grid with top and bottom lines sits behind the shelf (`.documents-shelf::before`); items rise in (360ms) unless the browser supports View Transitions; on a category change the filter runs in `document.startViewTransition()` and every item has its own `view-transition-name` (`documents-item-<id>`, inline) and every plank one per row (`documents-plank-<n>`, set by `renderPlanks()`), class `documents-item`, so books glide to their new spot or fade in and out over 0.4s (`::view-transition-group(*.documents-item)`; none with reduced motion or without support); and because the stretched button covers the cover, the cover hover lift and pressed state are driven from the item; the `+N` tag is `display: none` above 480px (see the software tags block). Grid: `repeat(auto-fill, minmax(min(100%, 200px), 1fr))`, `150px` at 820px and below, so the number of books per row follows the available width (2 on a phone, 5 at 1440px, 6 at 1920px: the Documents page is up to 1440px wide with the root side padding plus up to 32px, set in the shelf CSS on `.documents-page`, instead of the theme's 1040px) instead of fixed 4/3/2 steps (a deliberate change from the ticket); at 480px and below the description is clamped to 2 lines and only the first 2 tags show plus `+N`. With the Documents setting `show_book_title` off (the default), the shelf gets `documents-shelf--hide-titles`: the title text is not drawn (`font-size: 0`) but the button stays, named by its `aria-label`. Planks are created by `document-categories/view.js` and styled here (`.documents-shelf__plank`). Helper `devportfolio_document_shelf_item()`.
- `blocks/software-tags/` — reusable dynamic block `devportfolio/software-tags` (DPD-016), registered in `functions.php`, `usesContext: ["postId"]`, attribute `limit` (default 2). Renders the post's published `software_tool` names (`devportfolio_software_tool_names( $post_id )`, works for any post type storing `cptdp_software_tools`: document, video, collateral; also used by the modal payload) as `ul.software-tags` of `li.software-tags__item`, text separated by a gradient dot; nothing when there are none. Items after `limit` get `software-tags__item--extra` and, when there are any, a `li.software-tags__more` (`+N`, `title` lists the hidden names) follows. At 480px and below the extras are hidden and `+N` is shown; above that every tag shows. Colours are local tokens; the size is `--software-tags-size` (default 13.5px, 12.5px at 820px and below) so a parent can override it. Use it with `<!-- wp:devportfolio/software-tags /-->` inside a post context, or from PHP with `new WP_Block( array( 'blockName' => 'devportfolio/software-tags' ), array( 'postId' => $id ) )`. Tests: `tests/test-software-tags.php` (`Devportfolio_Test_Software_Tags`).
- `style.css` — theme header only
- `tests/` + `phpunit.xml.dist` — the theme test suite (main navigation, `Devportfolio_Test_Navigation`, `@group theme`); the bootstrap loads the WP test lib and the plugin; see Tests for the command and what it covers

- `blocks/document-modal/` — dynamic block `devportfolio/document-modal` (DPD-009/010/011/012/014/015), registered in `functions.php`, placed once in `archive-document.html`. `render.php` outputs one shared native `<dialog class="documents-modal">` (header, blank body for DPD-013, footer) plus a `<script type="application/json" class="documents-modal__data">` payload of every published document (`devportfolio_document_modal_payload()`: id, title, description, tools, format label, pages, download mode/URL). `view.js` (script module, imports `pager.js`) opens it on a click of any element with `data-document-id="<postId>"` (the `document-book` cover carries it; the DPD-016 item button must too), only when `(min-width: 701px)`; closes on backdrop click (click target is the dialog), Esc, the Close button, or shrinking to 700px or less. Header: serif bold title, one-line description (post excerpt, else first 20 words of the content), software pills, one `PDF · 24 pp` pill, Download link (`<a download>`; mode `file` = attachment URL, `embed` = embed URL in a new tab, `none` = `aria-disabled`), Close X button (last control of the same flex row as Download, same 36px height, so both align; Esc is the native `<dialog>` behaviour). Footer (hidden at <=700px): pager (Back, numbers, Next; <=9 pages all numbers, else 1, last, window of 3 each side or 2 in the two-page view, a one-page gap shows the page; visible pages filled; Back/Next `aria-disabled` at the ends; hidden for 1 page) and the indicator (`Pages 11–12 of 24` / `Page 5 of 24` plus a progress bar). Two-page view whenever `pages > 1` (always starts on an odd page). Page arrows (DPD-014): round Previous/Next buttons in the body, vertically centred, same `turnPage()` as the pager, `aria-disabled` + dimmed at the ends, shown only while hovering the body (`@media (hover: hover)`; always visible without hover, and on keyboard focus). The body holds the arrows and an empty `.documents-modal__stage`. State `{ id, page, step, pages }` is dispatched as `documents:modal-change` on the dialog for DPD-013 to fill `.documents-modal__stage`. `pager.js` is pure and tested with `node --test blocks/document-modal/tests/pager.test.mjs` (run from the block directory; Node 24 in DDEV: `ddev exec --dir=/var/www/html/wp-content/themes/devportfolio/blocks/document-modal node --test tests/pager.test.mjs`).

Testimonials and Contact are Home-page sections, linked as anchors `/#testimonials` and `/#contact`; the Home page sections need matching `id`s. Anchor links are never marked active.

## Conventions

- Prefer editing `theme.json`, templates and parts over adding PHP/CSS.
- Follow WordPress Coding Standards for PHP (tabs, Yoda conditions, escaping output with `esc_*`).
- Text domain: `devportfolio`; function prefix `devportfolio_`; any new pattern slug prefixed `devportfolio/`. Wrap user-facing strings in `esc_html__()` / `esc_html_x()` etc.
- Don't modify WP core files. Customise via the `devportfolio` theme or plugin. `twentytwentyfive` is reference only; do not edit it.
- Never commit secrets, DB dumps, or `wp-config.php`.
